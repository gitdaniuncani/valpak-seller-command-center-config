Seller Command Center

This guide shows how to rebuild the Seller Command Center in your own org. It covers two proven build paths: a Lightning page on Sales Home and a React app on Salesforce Multi-Framework. Both use the same data engine and both connect to Agentforce Coworker. Start with section 1 to pick the right path.

Pick Path 1 if your org runs on Lightning and wants the command center on the Home tab, maintained by admins without code, and it's fine for Coworker to open on its own page.
Pick Path 2 if your team builds in React, wants full design control, and wants Coworker as a chat on the same page. You'll run a separate app and do a few extra setup steps.

Both paths can run side by side, as they do in the reference org. Both read live data through the same Apex logic, so they show the same numbers.

2. Prerequisites

Both paths

  • Lightning Experience, the Sales app, and a sandbox to build in
  • Opportunity, Task and Event data (Amount, Stage, Probability, Close Date, Type)
  • Agentforce Coworker enabled. Sellers need the Coworker User permission set, and the global search Ask button must be visible.
  • Agentforce credits, which every Coworker conversation uses
  • Your deployment path (change sets, DevOps Center or CI/CD)

Path 1 — Lightning

  • VS Code + Salesforce Extensions (for the LWC)
  • Lightning App Builder access

Path 2 — React

  • An org on Hyperforce (Enterprise, Performance, Unlimited or Developer edition)
  • Salesforce Multi-Framework enabled, with the Salesforce App Domain active (Setup → Salesforce Multi-Framework Apps)
  • Salesforce Edge Network on, and "Require first-party use of Salesforce cookies" off (Setup → My Domain)
  • Node.js 20+ and npm, VS Code + Salesforce Extensions, and an up-to-date Salesforce CLI

3. The shared data engine

QuarterThe calendar quarter containing the as-of date (blank means today). This assumes a fiscal year starting in January; change the Context class if yours doesn't.
QTD Booked / % to quotaClosed Won Amount in the quarter ÷ goal. The goal is a setting (my goal and team goal), so no Forecasting quota object is required.
Selling days / paceWeekdays left in the quarter; pace = amount still to book ÷ selling days
Pacing indexBooked ÷ (goal × fraction of the quarter elapsed) × 100
Deal healthAt risk = past its close date, or closes within 3 days at 20% probability or less. Watch = closes within 7 days below 75%. Otherwise Healthy.
Insight cards (rule-based)Urgent = the largest at-risk deal · Revenue = the largest deal at 75% or higher closing within 7 days · Risk = the largest deal at 35% or lower closing within 7 days · Inventory = sample · Follow-up = proposals due this week plus overdue tasks
Needs Attention / TodayThe seller's open Tasks, oldest first, tagged SLA breach, Blocking, Warm or FYI. Today's Events, flagged Conflict or Prep gap; sample meetings show when there are none.
Sample tilesAvails, inventory mix, delivery watchlist, CPM, sell-through and Tableau views come from buildSample() until real sources are connected

Deploy the controller with its test class (about 98% coverage). Path 2 also needs SellerCommandCenterRest and its test (100%). Apps hosted on Multi-Framework can't call @AuraEnabled methods; they use Apex REST, GraphQL or the UI API instead.

4. Path 1 — Lightning page build

Build in a sandbox in this order, then promote.

  1. L1 · Static resources. In Setup → Static Resources, upload chartjs (Chart.js 4.4.4 chart.umd.min.js) and your logo (here valpakClippLogo), both with Cache Control set to Public. The names must match the component's imports.
  2. L2 · Apex. Deploy SellerCommandCenterController and its test (section 3). Deploy the Apex before the LWC.
  3. L3 · LWC sellerCommandCenter. Exposed to Home and App pages, with these settings: My quarter goal (11,200,000), Team goal (17,000,000), As-of date (blank means today), Default territory (MINE or ALL), and Coworker URL path (/lightning/coworker).
  4. L4 · Full-width home template. Create the Aura component commandCenterFullWidth (it implements lightning:homeTemplate, with a design file declaring one main region). The standard home templates limit the main area to about two-thirds of the page width.
  5. L5 · Home page. In Lightning App Builder, choose New → Home Page, pick the "Full Width (Single Region)" template, drag in Seller Command Center, set its properties, and save.
  6. L6 · Access. Create the Seller_Command_Center permission set with Apex class access to the controller (and to the REST class, for Path 2), and assign it to sellers.
  7. L7 · Activate. Go to Activation → App Default → Sales app → Desktop. Leave the org default unchanged so other apps keep their current Home page.
  8. L8 · Generate Seller Brief (full setup in section 4A). The button opens {Coworker URL path}?c__term=<brief request>&uid=<new id>. Coworker submits the request on load, using the dashboard's own figures. Nothing needs configuring in Coworker.

4A. Setting up the Seller Brief auto-trigger (Lightning page → Coworker)

Clicking ✦ Generate Seller Brief opens Agentforce Coworker and runs the brief request automatically, without the seller typing anything. There's no Flow, agent build or Prompt Builder template to create. It needs Coworker set up, one button in the component, and one page setting.

How it works

Seller clicks "✦ Generate Seller Brief"
   │  1. The component builds the brief request from the dashboard's live figures
   │  2. It opens:  {Coworker URL path}?c__term=<URL-encoded request>&uid=<new random id>
   ▼
Agentforce Coworker page loads
   │  3. Coworker reads c__term and submits it as the first message (auto-trigger)
   │  4. uid makes every click a fresh conversation
   ▼
Coworker searches the seller's Opportunities, Events and Tasks (as the seller)
and writes a three-part brief: Calendar & meeting prep · Dashboard · Prioritized next steps

Step 1 — Admin: make Coworker available to sellers

  1. Confirm Agentforce is enabled (Setup → Agentforce Agents) and that Agentforce Coworker is turned on (Setup → Agentforce Coworker).
  2. Confirm the Coworker agent (shown as Search Agent in Setup → Agentforce Agents) is Active.
  3. Assign these permission sets to every seller:
    • Agentforce Coworker User (API name AISearchUser)
    • Search Agent Access (API name SentOS_Agent_Access), which grants access to the Coworker agent
    • Admins who manage Coworker also get Agentforce Coworker Admin (AISearchAdmin)
  4. Check as a seller: the Ask button appears next to global search, and typing a question there offers Ask Coworker.

Permission set labels can vary slightly between releases and editions; search Setup → Permission Sets for "Coworker" and "Agent Access".

Step 2 — Confirm the Coworker page address in your org

  1. Signed in as a seller, type any question in global search and choose Ask Coworker.
  2. Look at the browser address bar. Today it reads /lightning/coworker?c__term=…&uid=….
  3. Note the path part (/lightning/coworker). That's the value for the page setting in Step 4.
This address isn't a published Salesforce API. It changed once already, in October 2026, from /lightning/search/agent (with c__ts) to /lightning/coworker (with uid). Repeat this check after each Salesforce release.

Step 3 — Developer: the button and the hand-off code (already in the component)

The button in sellerCommandCenter.html:

<button class="hdr-btn hdr-btn-primary" onclick={handleBrief}>✦ Generate Seller Brief</button>

The hand-off in sellerCommandCenter.js (the component uses NavigationMixin):

@api coworkerPath = '/lightning/coworker';   // exposed as a page setting (Step 4)

handleBrief() {
    this[NavigationMixin.Navigate]({
        type: 'standard__webPage',
        attributes: {
            url: `${this.coworkerPath || '/lightning/coworker'}?c__term=${encodeURIComponent(this.sellerBriefPrompt)}&uid=${newConversationId()}`
        }
    });
}

// A new random id per click so Coworker starts a fresh conversation
function newConversationId() {
    return 'xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx'.replace(/[xy]/g, (c) => {
        const r = Math.floor(Math.random() * 16);
        return (c === 'x' ? r : (r % 4) + 8).toString(16);
    });
}

The request itself is built from the dashboard so the brief matches what the seller sees:

get sellerBriefPrompt() {
    const base = 'Generate my seller brief. Summarize (1) my calendar for today and any meeting prep I need, ' +
                 '(2) my sales dashboard, and (3) my top next steps for today, prioritized.';
    // ...then appends live figures, e.g.:
    // "My dashboard: 90% to quota ($10.07M booked of $11.20M goal); 13 selling days left, $87K/day needed;
    //  weighted pipeline $3.39M across 138 open deals; $2.90M at risk across 64 deals (largest: Omega, Inc., $128K);
    //  12 overdue follow-up tasks."
}

Expose the path in sellerCommandCenter.js-meta.xml: <property name="coworkerPath" type="String" label="Coworker URL path" default="/lightning/coworker"/>

Step 4 — Admin: set the Coworker URL path on the page

  1. Open the Seller Command Center Home page in Lightning App Builder.
  2. Select the Seller Command Center component.
  3. In Coworker URL path, enter the path from Step 2 (default /lightning/coworker).
  4. Save. There's no need to reactivate.

Step 5 — Test it

  1. As a seller, open the Sales app Home tab and click ✦ Generate Seller Brief.
  2. Coworker opens and the request appears as the first message with no typing. Coworker shows steps such as "Finding Salesforce records (Opportunity / Event / Task)".
  3. The answer has three sections (Calendar & Meeting Prep · Dashboard Summary · Top Next Steps) with linked records.

What answers the brief

  • Agent: Coworker (Search Agent) using its standard "find Salesforce records" capability. It runs as the seller, so sharing and field security apply.
  • Prompt Builder: the seller brief uses no template. If a seller instead asks Coworker for an account brief, Coworker may use an account-brief action, for example "Create an Account Executive Brief" or a custom Valpak Account Brief template on a connected agent.
  • Credits: each brief uses Agentforce credits.

Customize the brief

  • Edit the wording or sections in sellerBriefPrompt, for example to add "competitive threats" or change the number of next steps.
  • Keep the request specific. Short requests like "seller brief" can be routed to other agents' topics, which then ask "which account?".
  • Keep figures concise. The full request travels in the page address.

Troubleshooting the auto-trigger

"Page doesn't exist"The Coworker address changed. Redo Step 2 and update the page setting in Step 4.
Coworker opens but nothing runsThe parameter name changed. Check the address from Ask Coworker for the current parameter (today c__term).
No Ask button, or access deniedThe seller is missing the Coworker User or agent access permission set (Step 1), or Coworker is off.
Coworker asks "which account?"The request was too short or vague. Use the full request built by sellerBriefPrompt.
Calendar section disagrees with the dashboardCoworker uses the real date while the page uses its as-of date. Clear the as-of date in production.

5. Path 2 — React app build (Salesforce Multi-Framework)

The React app runs on Salesforce. Salesforce signs the user in, hosts the files, and runs every data request with that seller's permissions.

  1. R1 · Confirm the org. Check that the org is on Hyperforce (Company Information shows an instance like USA876), that Salesforce Multi-Framework is enabled with an active App Domain, that Edge Network is on, and that the first-party cookie requirement is off.
  2. R2 · Generate the project. Create a project from Salesforce's React internal app template (reactinternalapp, documented in "Generate an App from a Template"). It includes the UIBundle, an App Launcher entry, an access permission set, and an Agentforce Conversation Client component.
  3. R3 · Install dependencies. In force-app/main/default/uiBundles/<app>: 
    npm install --include=dev        # include dev tools even if NODE_ENV=production
npm install @salesforce/agentforce-conversation-client@^12.11.0 chart.js@^4.4.4
npm run build                    # baseline build should pass before you change anything
  4. R4 · Apex REST. Deploy SellerCommandCenterRest (/services/apexrest/scc/v1/dashboard and /ask) with its test, and add it to the permission set. It wraps the shared controller and also returns meta: the org URL (for record links) and Coworker's agent ID.
  5. R5 · Data client. Call Apex REST through the Data SDK. It handles sign-in and CSRF, so there are no tokens in your code: 
    import { createDataSDK } from '@salesforce/platform-sdk';
const sdk = await createDataSDK();
const res = await sdk.fetch!('/services/apexrest/scc/v1/dashboard?scope=MINE&quarter=CURRENT&productType=ALL&asOfDate=2026-09-14&goal=11200000');
const dashboard = await res.json();
  6. R6 · Components. Port each section as a React component: Banner, KpiGrid, PacingChart, InsightsPanel, AvailsCard, WatchlistCard, OpportunitiesTable, TableauCard, TodayCard and NeedsAttentionCard. Add the Valpak palette as Tailwind theme tokens, and render the logo from src/assets. The app runs on its own domain, so record links must be absolute Lightning URLs that open in a new tab.
  7. R7 · On-page Coworker chat. Embed Coworker inline in a floating "messenger" panel (about 420×580px) with a launcher button. Keep it mounted while minimized, because the client embeds once per window. Use light message bubbles and override only the style tokens you need: 
    <AgentforceConversationClient
  agentId={meta.coworkerAgentId}          // Coworker = BotDefinition "SearchAgent" (0Xx…)
  inline width="100%" height="100%" headerEnabled={false}
  styleTokens={{
    messageBlockInboundBackgroundColor: '#dcf1fa', messageBlockInboundTextColor: '#0b2540',
    messageBlockOutboundBackgroundColor: '#f2f5f8', messageBlockOutboundTextColor: '#1b2a3a',
    messageBlockFontSize: '13px', messageInputFontSize: '13px',
  }} />
  8. R8 · Generate Seller Brief. Clicking it opens the chat with an instant seller brief snapshot built from live dashboard data: Today, the dashboard figures, and top next steps with record links. An Open full AI brief in Coworker ↗ button and a ↗ split button open the full AI brief in a new Coworker tab. The app also tries getAccEmbed().execute(request, agentId). If the org's embedded chat supports that bridge, the full request also runs inside the on-page chat. See section 6 for the current limits.
  9. R9 · Deploy and grant access. Run npm run build, then deploy the project's force-app folder (UIBundle, CustomApplication, permission set) with your usual tool. Rename the app's label (for example "Seller Command Center (React)") and assign the app's access permission set to sellers.
  10. R10 · Trust the app domain for the chat. In Setup → Session Settings → Trusted Domains for Inline Frames, add https://<mydomain>--c.my.salesforce.app with IFrame type Lightning Out. Without it, the Coworker panel stays blank. For local preview only, also add http://localhost:5173, and remove it before production.
  11. R11 · Open it. Use App Launcher → your app. The /lightning/app/… URL shows an empty Lightning app, because the React app is served from its own domain.

8. Customizing for your org

  • Goals, as-of date, territory, Coworker path: Lightning App Builder (Path 1); DEFAULTS in src/lib/scc.ts (Path 2). Leave the as-of date blank in production.
  • Brand: navy #204869, deep blue #002f6c, blue #00a0df, green #82bc00, alert #c23934, plus your logo. White card bodies with colored header bands.
  • Brief wording: sellerBriefPrompt in both front ends
  • Real media data: replace buildSample() with your inventory and delivery sources, then remove the Sample tags
  • Real quotas: read ForecastingQuota instead of the goal settings
  • Fiscal year: adjust the quarter maths in the Apex Context class
  • Thresholds: buildOppRows() and pick() in Apex

11. Rollback

Path 1: in Lightning App Builder, remove the page's App Default assignment for the Sales app. Sales Home immediately returns to the org default.

Path 2: remove the app's access permission set from users, or delete the UIBundle and its App Launcher entry. Remove the trusted Lightning Out domain if no longer needed.

Neither path changes existing records, pages or agents.
